## 💡 1. 프로젝트 개요

**우연한 식탁**은 매주 목요일 저녁 7시 30분, 서울 주요 4대 권역(홍대/합정, 잠실/송파, 강남/신논현, 을지로/종로)에서 4~6인의 엄선된 밥친구들을 연결해 주는 소셜 다이닝 서비스입니다.

- **안심 소셜 다이닝**: 연락처/실명/SNS를 노출하지 않고 닉네임과 취향 키워드로만 안전하게 소통
- **스마트 AI 매칭**: 연령차, 성비 균형, 관심사, 식사 예산대, 소통 성향, 기피/차단 회원을 다각도로 분석하여 최적의 테이블을 성사
- **자동화된 오퍼레이션**: 모임 신청부터 3단계 재매칭, 권역 제휴 식당 자동 예약, 단체 채팅방 개설, D-Day 리마인드 및 사후 피드백까지 전 과정 무중단 자동화

## ⭐ 4. 핵심 기능 (Key Features)

### 4.1 AI 매칭 시스템
- **다차원 성향 기반 테이블 추천**: 나이대(8세 이내), 관심사(음악, 운동, 독서, 맛집 등), 식사 예산대(2~3만 원, 3~5만 원 등), 소통 성향(경청형, 주도형, 리액션 부자 등)을 종합 채점하여 케미스트리가 극대화되는 4~6인 테이블 구성
- **엄격한 성비 균형 원칙 (Anti-Monopoly)**:
  - 남성만 있거나 여성만 있는 동성 테이블(4M/4F) 절대 생성 금지
  - 남녀 각각 최소 2명 이상 필수 배정 (2:2, 3:2, 2:3, 3:3)
- **3단계 순차 재매칭 & 무제한 안전망**:
  - 1차 매칭(월 12시) ➔ 2차 재매칭(월 21시) ➔ 3차 재매칭(화 08시)
  - 결원 및 취소자 발생 시 미배정 인원을 지속 재조합하며, 최종 미매칭 시 참가권 1회 즉시 100% 자동 환불
- **차단 및 기피 상호격리**: 비매너 피드백을 받거나 차단된 사용자끼리는 절대 동일 모임에 묶이지 않도록 하드 필터링

### 4.2 실시간 단체 채팅 및 안전 소통
- **안전한 라이프사이클 기반 채팅방 개설**:
  - 모임 신청 직후나 1~3단계 매칭 조율 중에는 채팅방 접근을 원천 차단
  - 화요일 정오 12:00 최종 확정 및 식당 예약이 완료된 모임에 한해서만 안전하게 채팅방 활성화
- **식당 상태 실시간 연동**:
  - 식당 배정 전에는 `식당 예약 전` 상태를 표시하여 혼선 방지
  - 예약 완료 시 식당 이름, 대표 메뉴, 네이버 지도 길찾기 링크가 대화방 상단 헤더에 동적 연동
- **WebSocket STOMP + HTTP Fallback 하이브리드 전송**:
  - WebSocket(`/ws-chat`) 연결을 통한 4인 실시간 대화 브로드캐스팅
  - 지하철 등 네트워크 음영 지역에서 웹소켓 단절 시 REST API(`/api/v1/chat/rooms/{id}/messages`)로 즉시 폴백 전송되어 전송 실패 제로 보장
- **모바일 PhoneFrame 밀착 UI**:
  - 스마트폰 뷰포트 내 상하단 공백 없는 100% 핏 레이아웃
  - 메시지 입력창 하단 밀착 고정 (`sticky bottom-0`) 및 우측 햄버거 메뉴를 통한 공지/멤버 리스트 확인

### 4.3 관리자 운영 콘솔 (Admin Operations)
- **전체 흐름 테스트 시뮬레이터 (`/admin/flow-test`)**:
  - 참가권 충전/회수, 1회권 결제, 1단계(신청/매칭)부터 9단계(식당 예약/채팅/피드백)까지의 전 주간 과정을 원클릭으로 단계별 즉시 시뮬레이션
  - 실제 DB 데이터(회원, 테이블, 슬롯, 알림, 결제)와 100% 동기화된 테스트 환경 제공
  - '매칭 정보 일괄 초기화(Reset)' 지원으로 반복 검증 지원
- **회차 및 권역 슬롯 관리 (`/admin/slots`)**:
  - 목요일 정기 회차 슬롯 및 서울 4대 권역 슬롯 생성 및 제어
  - 권역별 실시간 신청자 수, 목표 정원, 매칭 조 수, 대기자 수 대시보드
  - 특정 권역 마감 임박 시 실시간 '조기 마감 토글' 기능
- **매칭 운영 및 테이블 제어 (`/admin/matching`)**:
  - 권역별 생성된 모든 모임 조(테이블)의 실시간 목록 및 구성원 상세 스펙(나이, 직업, MBTI, 성비, 매칭 점수) 관제
  - 운영자 판단에 따른 회원 간 드래그 앤 드롭 수준의 수동 자리 맞바꾸기(Swap) 및 테이블 재조정
- **제휴 다이닝 풀 관리 (`/admin/venues`)**:
  - 서울 4대 권역별 분위기 좋은 소셜 다이닝 제휴 식당 데이터베이스 관리
  - 네이버 지도 플레이스 링크, 예약 가능 인원수, 대표 메뉴 연동
- **실시간 채팅 관제 및 긴급 공지 (`/admin/chat-ops`)**:
  - 활성화된 모든 조의 단체 채팅방 목록 실시간 로드 및 대화 내역 모니터링
  - 특정 테이블 또는 전체 권역 테이블을 대상으로 '운영자 긴급 공지' 메시지 즉시 브로드캐스팅 주입
- **1:1 고객센터 및 예외 큐 (`/admin/cs`, `/admin/exceptions`)**:
  - 사용자의 1:1 문의 실시간 응대 및 인원 미달/식당 미배정 등 운영 리스크 자동 감지 및 조치 큐 지원

### 4.4 참가 신청 및 식당 자동 배정
- **모바일 원터치 신청**: 매주 목요일 정규 모임에 대해 희망 권역(홍대, 잠실, 강남, 을지로) 선택 후 보유 참가권으로 간편 신청
- **권역 매핑 식당 자동 예약 배정**: 화요일 12:00 최종 확정 시 모임 권역(예: 홍대/합정)과 일치하는 제휴 식당 풀에서 최적의 매장을 알고리즘이 자동 예약 배정
- **도착 체크인 기능**: 모임 당일 식당 도착 시 '도착 체크인' 버튼을 통해 동행자들에게 착석 여부 실시간 공유

### 4.5 피드백 및 안심 매너 시스템
- **3대 다이닝 평가**: 음식 맛, 식당 분위기, 동행자 매너를 5점 척도로 평가
- **비공개 상호 평가 (Blind Feedback)**:
  - "이 멤버와 다음에도 함께하고 싶어요" (재매칭 가산점 부여)
  - "이 멤버와는 다시 만나고 싶지 않아요" (차단 등록 및 향후 AI 매칭 시 영구 배제)
- **매너 온도 시스템**: 긍정적 피드백 수집 시 개인 프로필 매너 점수 상승 반영

## 🏗️ 2. 전체 시스템 아키텍처

전체 서비스는 Docker Compose 기반의 5계층 마이크로서비스로 구성되어 독립적이고 유기적으로 동작합니다.

```
                                [Client Browser / Mobile Web]
                                              │
                                              │ HTTP (81) / WS (81)
                                              ▼
                                    [Nginx Reverse Proxy]
                      ┌───────────────────────┼───────────────────────┐
                      │ /                     │ /api/*, /ws-chat/*    │ /ai/* (내부망)
                      ▼                       ▼                       ▼
           [serendipity-frontend]   [serendipity-backend]   [serendipity-ai-engine]
           - React 18 (Vite SPA)    - Spring Boot 3.3.x     - Python 3.11 (FastAPI)
           - Mobile PhoneFrame      - Security + JWT (KST)  - Hard/Soft Constraint 매칭
           - Vanilla CSS Design     - WebSocket STOMP       - 조합 최적화 & 스코어링
                                              │
                                              │ JDBC / Redis
                                   ┌──────────┴──────────┐
                                   ▼                     ▼
                        [serendipity-postgres]   [serendipity-redis]
                        - PostgreSQL 15 (KST)    - Redis 7.x
                        - JSONB, TEXT[] 배열     - 세션, 캐시, 분산락
```

## 🚶 5. 핵심 사용자 흐름 (User Journey)

```mermaid
flowchart TD
    A[1. 회원가입 및 프로필 입력] -->|관심사, 성향, 식사 예산대 등록| B[2. 회차 및 권역 선택]
    B -->|참가권 결제 / 차감| C[3. 참가 신청 완료]
    C --> D{월~화 매칭 진행}
    D -->|1~3차 매칭 성공| E[4. 매칭 결과 확인 (멤버 카드 안내)]
    D -->|최종 매칭 실패| F[5. 무료 이월 / 참가권 자동 환불]
    E --> G[6. 화요일 12:00 최종 확정 & 식당 예약]
    G --> H[7. 4인 단체 채팅방 입장 & 사전 스몰토크]
    H --> I[8. 목요일 저녁 19:30 식탁 참석 & 도착 체크인]
    I --> J[9. 금요일 12:00 3대 별점 피드백 & 비공개 비매너 차단]
```

1. **회원가입 및 온보딩**: 성별, 출생연도, 직업, MBTI, 관심사(복수선택), 나의 성향 및 선호 성향, 식사 예산대 등록
2. **참가 신청**: 희망 회차(목요일 저녁)와 서울 4대 권역 중 하나를 선택하여 참가권으로 신청
3. **매칭 대기 및 조율**: 신청 마감 시점(월요일 12:00)부터 AI 매칭 알고리즘 가동
4. **멤버 카드 선공개**: 매칭 성공 시 익명화된 동행자들의 나이대, 직업, MBTI, 매칭 점수 확인
5. **최종 확정 및 식당 예약 (화요일 12:00)**: 권역 내 맞춤형 다이닝 식당이 배정되고 4인 단체 채팅방 오픈
6. **실시간 소통 & 도착 체크인**: 채팅방에서 아이스브레이킹 대화 및 식당 도착 시 도착 체크인 수행
7. **사후 피드백 & 리텐션**: 식사 완료 후 맛/분위기/매너 3대 평가 및 비공개 재매칭 희망/기피 멤버 선택

## ⏱️ 6. 모임 주간 라이프사이클 (Zero-Touch Lifecycle)

Spring Boot의 `@Scheduled(cron = "...", zone = "Asia/Seoul")` 스케줄러를 통해 한 주간의 모임 운영이 사람의 개입 없이 완전 자동화됩니다.

| 일시 (KST) | 라이프사이클 단계 | 시스템 동작 상세 |
| :--- | :--- | :--- |
| **매주 월요일 09:00** | **차주 회차 자동 생성** | 차주 목요일(D+10) 정기 회차 슬롯 및 4개 권역 슬롯 자동 등록 |
| **매주 월요일 12:00** | **1차 AI 매칭 엔진 가동** | 신청 마감자 대상 권역별 1차 AI 매칭 실행 및 배정자 멤버 리스트 발송 |
| **매주 월요일 21:00** | **2차 AI 재매칭 가동** | 1차 미매칭자 및 참가 취소자로 결원이 발생한 그룹 대상 2차 재매칭 |
| **매주 화요일 08:00** | **3차 최종 재매칭 & 실패 반환** | 최종 3차 재매칭 실행. 최종 미매칭자에게 **참가권 1회 자동 반환** 및 알림 발송 |
| **매주 화요일 12:00** | **최종 확정 & 식당 예약 & 채팅방 개설** | 매칭 테이블 `CONFIRMED` 전환, 권역별 제휴 식당 자동 배정, **4인 단체 채팅방 공식 개설** |
| **매주 화요일 16:00** | **식당 미예약 예외 감지** | 제휴 식당 예약 실패 테이블 감지 시 관리자 **예외 큐(Exception Queue)**로 자동 이관 |
| **매주 목요일 12:00** | **모임 당일(D-Day) 리마인드** | 당일 참석자 전원 및 채팅방에 식당 위치, 지도 링크, 집결 안내 푸시 발송 |
| **매주 목요일 19:00** | **모임 30분 전 알림** | 모임 30분 전 리마인드 발송 및 "식당 도착 후 도착 체크인" 안내 |
| **매주 목요일 19:30** | **식탁 시작 환영 공지** | 정규 모임 시작 안내 및 매너 수칙 리마인드 공지 자동 발송 |
| **매주 금요일 12:00** | **사후 다이닝 피드백 요청** | 어제 참석자 전원에게 3대 평점(음식/분위기/매너) 및 비공개 재매칭 평가 요청 발송 |

## 🧠 7. AI 매칭 엔진 알고리즘 (Matching Algorithm)

`ai-engine` 서비스(FastAPI)는 **하드 제약 조건(Hard Constraints)**을 엄격하게 필터링한 후, **소프트 조건(Soft Scoring)** 가중치 모델을 기반으로 최적의 4~6인 테이블 조합을 탐색합니다.

### 7.1 하드 제약 조건 (Hard Constraints - 절대 타협 불가)
1. **인원수 제약**: 한 테이블은 반드시 **4인 ~ 6인**으로만 구성
2. **최대 연령 차이**: 테이블 내 **(최고 연령 - 최저 연령) ≤ 8세** 엄수
3. **성비 균형 강제 (동성 테이블 금지)**:
   - 남성만 있거나 여성만 있는 **동성 테이블(4M / 4F) 완전 배제**
   - 남성과 여성 모두 **최소 2명 이상 필수 포함 (2:2, 3:2, 2:3, 3:3)**
4. **차단 및 기피 관계 분리**: 과거 비매너 신고자, 시스템 차단자(`user_blocks`), 상호 기피 회원은 동일 테이블 배치 절대 불가

### 7.2 소프트 가중치 스코어링 (Soft Scoring - 100점 만점)
$$\text{Total Score} = S_{\text{age}} + S_{\text{ratio}} + S_{\text{interest}} + S_{\text{budget}} + S_{\text{tendency}}$$

| 평가 항목 | 배점 | 산출 공식 및 기준 |
| :--- | :---: | :--- |
| **연령 점수 ($S_{\text{age}}$)** | **25점** | $\max(0, 25.0 - (\text{age\_diff} \times 2.5))$ (동갑일 때 25점, 8세 차이 시 5점) |
| **성비 점수 ($S_{\text{ratio}}$)** | **30점** | 남녀 2:2 / 3:3 완벽 균형 시 **30.0점**, 5인(3:2 또는 2:3) 시 **26.0점** |
| **관심사 점수 ($S_{\text{interest}}$)** | **20점** | 공통 관심사 집합 교집합 수에 비례: $\min(20.0, \text{len(common)} \times 6.0 + 8.0)$ |
| **예산대 점수 ($S_{\text{budget}}$)** | **15점** | 구성원 전체가 교차 허용하는 식사 예산대 구간 존재 시 **15.0점** (불일치 시 8.0점) |
| **소통 성향 점수 ($S_{\text{tendency}}$)** | **10점** | 나의 성향 키워드와 상대방의 선호 성향 간의 적합도 평가 (기본 10.0점) |

### 7.3 탐색 알고리즘
- `itertools.combinations` 기반 조합 탐색에 **Early Pruning(조기 가지치기)**을 결합
- 조합 탐색 시 기준 점수 **45.0점 이상**의 최적 조합을 우선 확정하고, 잔여 인원에 대해 5/6인 병합 탐색 수행
- 외부 AI Engine 일시 장애 시, 백엔드 내부의 **안전 Fallback 휴리스틱 엔진**이 동일한 성비/인원 제약으로 자동 폴백 처리

## 💬 8. 실시간 단체 채팅 및 공지 아키텍처

- **개설 시점 제어**: 1~3단계 매칭 대기 중에는 개설되지 않으며, **4단계(화요일 정오 12:00) 최종 확정 및 식당 예약 완료 시점**에만 안전하게 생성/입장 허용
- **식당 예약 전 표시**: 식당 예약이 조율 중이거나 미완료된 경우 식당명 대신 **`식당 예약 전`**으로 안전하게 표시
- **WebSocket STOMP + HTTP Fallback**:
  - WebSocket(`/ws-chat`) 연결 시 STOMP 엔드포인트 `/pub/chat/message` 및 `/sub/chat/room/{roomId}`로 실시간 브로드캐스팅
  - 네트워크 단절이나 일시적 연결 지연 시 `/api/v1/chat/rooms/{roomId}/messages` REST API로 즉시 폴백 전송되어 메시지 유실 방지
- **모바일 화면 최적화**: 
  - 모바일 PhoneFrame 내에서 상하 흰색 여백 없이 100% 꽉 차는 레이아웃 적용
  - 메시지 입력창이 화면 최하단에 항상 밀착되는 `sticky bottom-0 z-30` 고정 디자인

## 🖥️ 9. 관리자 운영 콘솔 상세 (Admin Console)

관리자 전용 웹 경로(`/admin`)를 통해 서비스의 전 과정을 실시간으로 모니터링하고 제어할 수 있습니다.

- **전체 흐름 테스트 시뮬레이터 (`/admin/flow-test`)**:
  - 1회권 결제 및 참여권 지급/회수 실 DB 연동
  - 1단계(월 12시)부터 9단계(금 12시)까지의 전체 모임 라이프사이클을 버튼 하나로 즉시 단계별 시뮬레이션
  - 매칭 정보 및 알림 내역 일괄 초기화(Reset) 지원
- **회차 및 권역 슬롯 관리 (`/admin/slots`)**:
  - 목요일 정기 회차 생성, 권역별 실시간 신청/매칭/대기 인원 집계
  - 권역별 '조기 마감' 실시간 토글 제어
- **매칭 운영 및 테이블 제어 (`/admin/matching`)**:
  - 확정 테이블 목록 및 조별 상세 구성원(나이, 직업, MBTI, 성비) 확인
  - 회원 간 수동 자리 맞바꾸기(Swap) 및 테이블 수동 제어
- **제휴 식당 풀 관리 (`/admin/venues`)**:
  - 서울 4대 권역별 실제 네이버 지도 플레이스 링크 및 대표 메뉴 연동
- **채팅 관제 및 긴급 공지 (`/admin/chat-ops`)**:
  - 개설된 전체 단체 채팅방의 실시간 대화 모니터링
  - 권역별 또는 전체 단체방 대상 긴급 운영자 공지 주입 브로드캐스트
- **1:1 CS 고객센터 및 예외 큐 (`/admin/cs`, `/admin/exceptions`)**:
  - 식당 미배정, 인원 미달 등 시스템 이상 징후 자동 감지 및 관리자 수동 개입 지원
